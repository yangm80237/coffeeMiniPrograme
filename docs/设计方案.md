| # | 决策项 | 结论 |

| 1 | 技术栈 | 原生小程序（WXML+WXSS+JS）+ 微信云开发 |

## 二、四阶段实施策略

| 阶段 | 内容 | 验证方式 |
|---|---|---|
| ① 视觉稿定稿 | prototype.html 升级为 BeanBook 插画风终稿，含新增统计页 | 浏览器逐屏确认 |
| ② 小程序前端全量 | 原生小程序 + mock 数据，全部页面可操作；同时初始化云开发环境、建 3 个集合 | 开发者工具模拟器 + 真机预览 |
| ③ 数据真实接入 | `api/` 层从 mock 切换到云开发，部署云函数；页面代码零改动 | 真机两人联调 |
| ④ AI 能力接入 | 云函数接火山方舟（识别 + 生图），风味图标批量生成，真机联调收尾 | 真机全流程验证 |

核心机制：`api/` 层接口签名与云开发调用一致，mock 与真实实现可切换，阶段③只换数据源实现。

## 四、工程结构（阶段②产出）

```
coffeeApp/
├── miniprogram/
│   ├── pages/            # 规格书9页 + pages/stats/stats（统计页）
│   ├── components/       # bean-card / attribute-tile / rating-stars / flavor-tag / status-badge
│   ├── styles/tokens.wxss
│   ├── api/              # bean.js / brand.js / flavor.js / stats.js
│   ├── mock/             # 各状态豆子样例数据
│   └── utils/            # status.js 养豆期计算 / format.js
├── cloudfunctions/       # 阶段③④填充：recognizeBean / genFlavorIcon
└── docs/
```

- `attribute-tile` 组件四参数化（形状/颜色/图标/文案），磁贴由配置数据驱动渲染。
- `utils/status.js` 为纯函数，TDD 开发（养豆期规则表来自规格书 3.3）。

## 五、统计页与 AI 接入设计

### 统计页（pages/stats/stats）

- 顶部汇总：总克重、品牌数、产区数、豆种数
- 分布：状态三色占比、处理法计数、产区 Top
- 产区地图：**canvas 2D 风格化世界地图 + 产区标注点**（替代 BeanStats 的 3D 地球仪；WebGL 成本高一个量级，2D 意境接近）
- 底部：烘焙商数 / 袋数 / 产区数 / 豆种数 四指标

### 火山方舟接入（阶段④）

| 用途 | 模型 | 说明 |
|---|---|---|
| 拍照识别豆袋 | `doubao-seed-1.6`（视觉理解，JSON 输出） | 备选降级 `doubao-1.5-vision-lite` |
| 水彩风味图标 | `doubao-seedream-4.0` | 统一 prompt 沿用规格书 3.6 |

- 云函数 `recognizeBean`：图片云存储 fileID → 豆包多模态 → 结构化 JSON（字段表见规格书 3.2.1）→ 自动匹配品牌/风味。
- 云函数 `genFlavorIcon`：按名称生成水彩图标 → 传云存储 → 写 `flavor_tags.iconUrl`。
- API Key 与 Endpoint ID 放云函数环境变量，不进代码库；识别目标 < 5 秒。

## 六、superpowers 工作流映射

| 技能 | 用在哪 |
|---|---|
| writing-plans | 设计定稿后拆实施计划 |
| executing-plans / subagent-driven-development | 按 P0 任务批执行，每批检查点 |
| test-driven-development | utils/status.js、筛选排序、评分均值等纯函数 |
| dispatching-parallel-agents | 相互独立的页面/组件并行开发 |
| systematic-debugging | 阶段③④联调问题 |
| verification-before-completion | 每阶段收尾真机验证 |
| requesting-code-review | 阶段结束自查 |

注：TDD 适用于逻辑代码；视觉稿阶段靠人工逐屏确认。

## 七、风险与取舍

| 风险 | 对策 |
|---|---|
| 小程序不能内嵌自定义字体 | 中文衬线用 Songti SC/STSong 系统字体 fallback，安卓退化为宋体，可接受 |
| 3D 地球仪成本高 | 降级为 canvas 2D 风格化地图（本设计已采纳） |
| 风味图标依赖生图 API | 前端先行占位，图标生成集中在阶段④一次完成 |
| 审核类目 | 个人主体建议「生活服务」或「工具 > 信息查询」 |
