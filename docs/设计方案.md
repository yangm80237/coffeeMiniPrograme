核心机制：`api/` 层接口签名与云开发调用一致，mock 与真实实现可切换，阶段③只换数据源实现。

### 阶段③部署指引（用户在 DevTools 执行，一次性）

1. **建集合**：云开发控制台 → 数据库 → 依次创建 6 个集合：`families` / `users` / `brands` / `beans` / `flavor_tags` / `config`（权限默认即可，云函数绕过权限）
2. **部署函数**：DevTools 左侧目录 `miniprogram/cloudfunctions/` 下 7 个函数（user/bean/brand/flavor/stats/admin/init）逐个**右键 → 上传并部署：云端安装依赖**
3. **跑种子**：DevTools → 云开发 → 云函数 → init → 云端测试（入参 `{}`）→ 期望返回 `{brandsInserted:12, flavorsInserted:45}`，重跑应为 0/0（幂等）
4. **验证**：编译 → 首启绑定家庭 → 入库（照片自动上云存储）→ 让太太输码加入 → 两人互见同一份库存
5. 常见问题：函数目录右键若无「上传并部署」选项 → 检查 project.config.json 的 `cloudfunctionRoot` 为 `cloudfunctions/` 且 DevTools 重新打开项目；报 `NO_FAMILY` → 属正常鉴权，先走绑定流程

> 阶段②遗留项（不阻塞，阶段③④处理）：照片上传云存储（当前 mock 用临时路径）；AI 真识别（processing 页 mock 4s）；风味图标 Seedream 生成（emoji 占位）；「再加一张」照片追加（photo-strip add 事件未接）；粘贴链接入库（P2）；微信开发者工具真机编译与渲染实测（无人值守环境仅静态校验）。

### AI识别中页冲煮动画（10秒循环）

3颗咖啡豆晃动碎成粉末 → 落入 V60 滤杯 → 细口壶滑入倾斜注水 → 咖啡滴入玻璃分享壶、液面渐升 → 淡出重来；提示文案轮播 5 条 + 跳过按钮。H5 原型纯 CSS 实现；小程序方案：CSS 动画直接迁移，效果不足时升级 Lottie。

## 五、统计页与 AI 接入设计

### 统计页（pages/stats/stats，原型已定稿）

- 深色汇总头：总克重、品牌数、产区数、豆种数
- 状态分布：三色占比条 + 各状态袋数
- 处理法计数 → **国家分布横条图**（国旗emoji+国名+渐变条+袋数）→ **豆种分布横条图**
- 产区地图：**canvas 2D 风格化世界地图 + 产区标注点**（替代 BeanStats 的 3D 地球仪；WebGL 成本高一个量级，2D 意境接近）
- 底部：烘焙商数 / 袋数 / 产区数 / 豆种数 四指标

### 火山方舟接入（阶段④）

| 用途 | 模型 | 说明 |
|---|---|---|
| 拍照识别豆袋 | `doubao-seed-1.6`（视觉理解，JSON 输出） | 备选降级 `doubao-1.5-vision-lite`；识别字段含国家+产区（拆分） |
| 水彩风味图标 | `doubao-seedream-4.0` | 统一 prompt 沿用规格书 3.6 |

- 云函数 `recognizeBean`：图片云存储 fileID（含识别主图）→ 豆包多模态 → 结构化 JSON（字段表见规格书 3.2.1）→ 自动匹配品牌/风味。识别期间前端停在冲煮动画页，完成后自动跳核对页（保留跳过）。
- 云函数 `genFlavorIcon`：按名称生成水彩图标 → 传云存储 → 写 `flavor_tags.iconUrl`。
- API Key 与 Endpoint ID 放云函数环境变量，不进代码库；识别目标 < 5 秒。

## 六、双人身份与家庭边界（2026-09-07 定稿）

**原则**：openid 免登录天然区分"是谁"（云函数 `getWXContext().OPENID`，零成本）；邀请码解决"谁能进"——正式发布后任何陌生人都能打开小程序，需要家庭边界。

### 流程

| 环节 | 设计 |
|---|---|
| 创建者首次打开 | 检测无家庭 → 引导「创建家庭」→ 自动生成 6 位邀请码（如 `K7F2QX`），角色 `owner` |
| 成员加入 | 首次打开输入邀请码 → 绑定 `familyId`，角色 `member` |
| 防滥用 | 家庭人数上限 2~4；邀请码可在「我的」页随时关闭/重新生成 |
| 昵称头像 | 微信官方「头像昵称填写能力」（`chooseAvatar` 按钮 + nickname 输入框），不依赖已受限的 getUserProfile |
| 评价署名 | ratings 记录 openid + 快照昵称头像，两人独立打分 |

### 数据模型

```
families: { _id, inviteCode, inviteEnabled, createdAt }
users:    { _openid, nickname, avatarUrl, familyId, role: 'owner'|'member', createdAt }
beans / brands / flavor_tags / ratings / ai_logs: 全部带 familyId（而非 openid），实现家庭共享读写
```

- 所有数据读写走云函数（阶段③ `api/` 层切换），云函数内校验调用者 `openid ∈ 某家庭` 后按 `familyId` 读写， strangers 无家庭身份一律拒绝
- 页面增量：新增「家庭绑定页」（首启引导/输码）+ 「我的」轻页（头像昵称、邀请码管理、退出家庭）+ 「管理页」（owner 专属，模型 ID 等运行时配置维护）；计入阶段②页面清单（共 16 页）

## 七、AI Key 与模型配置管理（2026-09-07 定稿）

**铁律**：API Key 绝不进小程序前端（包体可被反编译提取），也不在管理页展示/维护。

| 决策点 | 方案 |
|---|---|
| Key 存放 | 云函数环境变量 `ARK_API_KEY`（云开发控制台配置，换 key 不发版，前端零接触） |
| 模型 ID | **config 集合运行时读取**，「管理页」（owner 专属）在线维护，保存即生效，无需发版 |
| 配置回退 | 云函数优先读 `config` 集合；为空/读取失败时回退环境变量默认值（`ARK_MODEL_VISION` / `ARK_MODEL_IMAGE`），保证冷启动与误清空时可用 |
| 调用链 | 前端只传照片 fileID → 云函数校验家庭身份 → 读模型配置 → 调方舟（OpenAI 兼容协议）→ 仅回传识别 JSON |
| 防滥用 | 家庭身份校验天然限流（仅 2 人可调）；超时 8s + 1 次重试 |
| 成本可观测 | 每次调用写 `ai_logs`（模型、耗时、token/张数、成败、openid），随手看用量 |

### 模型配置（config 集合）

```
config: { _id: 'ark', modelVision: 'doubao-seed-1.6', modelImage: 'doubao-seedream-4.0', updatedAt, updatedBy }
```

- 模型 ID 支持填模型名（`doubao-seed-1.6`）或推理接入点 ID（`ep-xxxxxx`），方舟两种皆可
- 管理页（pages/admin/admin，仅 `role='owner'` 可见入口）：视觉/生图两个模型 ID 输入框 + 保存 + （P2）连通性测试；显示当前实际生效值（config 或回退来源）
- 云函数 `getConfig`（家庭内可读）/ `updateConfig`（仅 owner 可写）；云函数侧可对 config 做 60s 内存缓存，量小可先不加

`recognizeBean` / `genFlavorIcon` 封装全部 AI 细节，前端零感知；换模型改管理页即生效，换 key 改控制台环境变量，两者都无需发版。

## 九、风险与取舍

| 风险 | 对策 |
|---|---|
| 小程序不能内嵌自定义字体 | 中文衬线用 Songti SC/STSong 系统字体 fallback，安卓退化为宋体，可接受 |
| 属性 PNG 图标未到位 | 原型/前端用 emoji 占位（结构已留 iconUrl 位），PNG 到位后直接替换，无代码改动 |
| 3D 地球仪成本高 | 降级为 canvas 2D 风格化地图（本设计已采纳） |
| 冲煮动画小程序性能 | 先 CSS 动画迁移；不足时 Lottie；极端降级为静态插画+加载文案轮播 |
| 风味图标依赖生图 API | 前端先行占位，图标生成集中在阶段④一次完成 |
| 审核类目 | 个人主体建议「生活服务」或「工具 > 信息查询」 |
